# 九人圆桌 · 头脑风暴

一个可联网获取前沿新闻的 Windows 桌面头脑风暴工具：让九个不同职责的模拟角色围绕主题讨论，再整理成机会方向、风险和验证行动。

## 当前版本

- 九个默认角色，默认全部参与；支持全选、全不选和快速四人模式。
- 中央提供赌场绿色圆桌视图，九个固定席位显示原创头像、姓名和参与/当前发言状态。
- 圆桌讨论由用户点击“下一句”逐条推进；讨论没有固定轮次上限，播放到当前记录末尾会继续追加回应、补充和反驳，同一角色可以多次发言，用户点击“结束并总结”后才进入机会档案。
- 主持人独立负责开场、阶段总结和机会卡，不占九个讨论席位。
- 支持输入讨论主题和一条前沿消息/趋势线索。
- 大厅默认勾选本次获取相关新闻；新闻在独立后台抓取，失败不会阻止圆桌开始。
- 角色模板讨论不需要 API Key；联网 RSS 与真实模型调用是两项独立能力。
- 明确区分机会、风险、假设、事实和待验证内容。
- 生成目标用户、支持理由、主要风险、待验证假设和下一步行动。
- 结束后进入独立的机会档案总结页，完整展示讨论统计、来源状态和验证行动。

RSS 使用主题检索及 BBC、Guardian 等公开 HTTPS 订阅源，聚合社会议题、世界、商业、科技、科学与环境信息，按发布时间排序。订阅源只代表其实际发布且与主题匹配的内容，不覆盖全网。新闻标题、链接、摘要、发布时间和获取状态会保存在记录中，并始终标记为“未核验”。

九个席位是预设的不同职责视角，不是九个真实人物或九个独立 AI。默认讨论来自代码中的离线角色模板：首轮围绕主题表达职责视角，续轮结合已有讨论和用户插话；RSS 只作为单独展示的外部素材，模板模式不会假装完成新闻语义分析。若用户另外配置并明确允许真实 Anthropic 模型，模型才会依据角色职责、主题、历史发言、用户线索和 RSS 摘要生成观点；模型输出依旧是待核验推断。

## 运行

需要 Python 3.10 或更高版本，以及 PySide6：

```text
python -m pip install PySide6
python app.py
```

首次开始讨论时，大厅默认选中“允许本次讨论获取 RSS 前沿信息”，用户可取消；只在点击开始时联网。若系统网络设置禁止联网或配置 `BRAINSTORM_MODE=offline`，新闻选项不可用，强制离线边界不会被 RSS 或 API Key 绕过。可使用 `BRAINSTORM_ALLOW_NETWORK=0` 关闭网络，或通过 `BRAINSTORM_RSS_FEEDS` 替换 RSS 地址（多个 HTTPS 地址用逗号分隔；`{query}` 会替换为 URL 编码后的主题）。

真实模型默认关闭。只有显式允许网络、设置 `BRAINSTORM_MODE=llm`、`BRAINSTORM_ALLOW_LLM=1` 并提供 `BRAINSTORM_LLM_API_KEY`（或 `ANTHROPIC_API_KEY`）后，才会调用模型。API Key 不写入讨论档案。新闻与模型观点均标记为未核验，失败时诚实回退或继续离线模拟。

## OpenAI 兼容模型

桌面版可在大厅点击“AI 设置”，填写接口地址、模型名称和 API Key，勾选启用后保存。设置从下一次讨论生效；密钥由 Windows 为当前用户加密保存于本机用户数据目录，不随桌面包分享。保存不代表连接成功，真实请求失败时会明确回退。

项目支持标准 `/v1/chat/completions` 格式，可接 OpenAI、DeepSeek、硅基流动、通义等兼容服务。启用前设置以下环境变量，然后重新启动软件：

```text
BRAINSTORM_MODE=llm
BRAINSTORM_ALLOW_LLM=1
BRAINSTORM_LLM_PROVIDER=openai
BRAINSTORM_LLM_BASE_URL=https://api.openai.com/v1
BRAINSTORM_LLM_MODEL=gpt-4o-mini
BRAINSTORM_LLM_API_KEY=你的密钥
```

`BRAINSTORM_LLM_BASE_URL` 应填写服务商的 v1 根地址，不要重复写 `/chat/completions`。API Key 只从运行环境读取，不会打包进桌面版、历史记录或导出文件。请求失败、返回格式错误或取消时会安全回退到离线角色模板。

运行测试：

```text
python -m unittest discover -s tests -v
```

## 打包 EXE

如果已安装 PyInstaller，请使用 Qt spec（不要使用旧的 Tkinter spec）：

```text
pyinstaller --noconfirm --clean --distpath dist-qt --workpath build-qt 九人圆桌-Qt.spec
```

输出在 `dist-qt/九人圆桌-Qt/`。建议先使用 one-folder 版本确认 Qt 平台插件、头像和中文字体正常，再按需要制作 one-file 版本。

D 阶段旧包 `dist-stage-d/` 曾混入 Poppler 的不兼容 ICU DLL，启动时会报 QtCore 导入错误。原来仅检查进程存活的验证不能识别异常弹窗，因此该旧包不再作为可运行版本。

修复包位于 `dist-qt-repair/九人圆桌-Qt/`，桌面交付文件夹为 `九人圆桌桌面版`，入口是 `九人圆桌.exe`。Qt spec 限制打包时的 DLL 搜索路径，让 Qt 使用 Windows 系统 ICU；保留全部历史发布目录。Windows 窗口回归工具 `desktop-release/verify-packaged-app.py` 和 `verify-main-window.ps1` 验证可见 Qt 主窗口，并将异常弹窗判为失败。

UI 的来源面板、总结页和 Markdown 导出会说明九人观点如何生成，并将 RSS 新闻与用户提供的线索分开列出。
# 九人圆桌

九人圆桌是一款中文优先的 Windows 桌面头脑风暴工具。它默认离线运行，让九个稳定角色围绕主题进行无限混合讨论。

## 讨论模式

- 主持人开题后，九个角色先给出独立观点，再进入动态交锋。
- 讨论没有固定总轮数；角色可以多次发言、支持、反驳、追问和补充，也可以在被说服后明确改变立场。
- 系统根据新观点密度、重复、冷场和分歧状态自动插入主持人整理。
- 用户可随时插话、暂停、继续或点击“结束并总结”。插话会进入下一批发言的高优先级上下文。
- 圆桌记录保存事件顺序、回应对象、回应意图、来源和立场变化；总结页显示共识、未解决分歧、未回答问题、未验证假设和行动建议。

离线观点会明确标记为模拟内容；真实模型和 RSS 内容仍标记为未核验。历史记录从本地加载，不会自动联网或重新生成。
