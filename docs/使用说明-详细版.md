# 九人圆桌 · 详细使用说明

版本：2026-10-27　　适用：Windows 桌面版（`九人圆桌.exe`）

---

## 一、这是什么

你输入一个主题，**九个固定社会／职业视角**围绕它讨论：趋势分析师、行业从业者、创业实践者、技术与实现顾问、真实需求者、普通路人、用户研究员、跨界创意者、怀疑者／风险评审。另有一个**主持人**负责开题和收束，不占九个席位。

讨论由**你**控制节奏，你点一次走一条。你随时可以插话、暂停或结束；结束后生成一份**机会档案**。

大厅右侧可以切换**两个分区**，两套人完全不同：

| 分区 | 坐几个人 | 讨论什么 | 产出 |
| --- | --- | --- | --- |
| **商业痛点**（默认） | 九个社会／职业视角 | 一个问题值不值得做、谁真的需要 | 机会档案 |
| **事件讨论** | 八个以八卦为性格原型的人 | 一件已经发生的事，谁说了什么、信哪个版本 | 吃瓜纪要 |

必须先说清的一点：**桌上的人都是同一个 AI 模型扮演的不同视角，不是真人，也不是多个独立模型账户。** 商业痛点分区九个人，事件讨论分区八个人。没有配置真实模型时，程序用内置的离线模板模拟，界面会明确标注。

---

## 二、启动

1. 双击程序文件夹里的 **`九人圆桌.exe`**（或桌面快捷方式）。
2. 无需安装 Python 或 PySide6。
3. 启动后**默认全屏**。按 `Esc` 或点「窗口化」会一档一档缩小：全屏 → 大窗 → 小窗 → 又回到全屏。**它不会退出程序，也不会最小化成任务栏里的一条**；真想关，点右上角「退出」。

> 移动或复制这个软件时，请保留**整个文件夹**（尤其是 `_internal`），只复制 exe 会无法运行。

---

## 三、第一次使用：配置 AI

没有配置也能用（走离线模板），但要真正调用大模型，需要填一次设置。

1. 大厅右上角点击 **「AI 设置」**。
2. 勾选 **「启用 AI 讨论（会调用所填服务）」**。
3. 填三项：
   - **接口地址**：OpenAI 兼容格式的地址，例如 `https://api.deepseek.com/v1`
   - **模型名称**：服务商给的模型名，例如 `deepseek-chat`
   - **API Key**：你自己的密钥
4. 点保存。

关于密钥，三件事请放心也请知道：

- 密钥用 **Windows 当前用户的加密（DPAPI）** 保存，文件在
  `%LOCALAPPDATA%\九人圆桌\ai-settings.json`。
- 它 **不会**进入程序文件夹，**不会**进入导出文件，**不会**进入你发给别人的分享包。
- **保存设置不等于连接成功。** 下一次讨论才会使用；是否真的连上，看大厅的状态提示（见下一节）。

## 四、大厅

大厅就是一桌牌：

- **挑桌**：标题下面两个按钮「事件讨论　→　吃瓜纪要」和「商业痛点　→　机会档案」，点一下就整桌人换掉，当前分区用金色高亮。
- **牌就是人**：中间那张绿绒台面上摊着这个分区的人，一人一张牌，牌上写着名字和这个人干什么的。**点一下牌就翻过去，这一位就不上桌了**；再点一下翻回来。最少留两个人——只剩一个人就没人吵了，程序会提示你。
- **发牌／重新发牌**：刚进来牌是一叠扣着的（牌背压一个「九」字），按「发牌」按顺序摊开；牌已经摊开时按钮变成「重新发牌」，按一下全部收回牌堆、所有人恢复在桌。
- **聊什么**：台面下方那张票上写议题，越具体越好。右边「换一个」给你一句例子。
- **补充材料（可选）**：粘贴来龙去脉、数据或链接。写了会当素材，但不代表已经核实。
- **开桌**：右下角的金按钮。旁边的小字写着「桌上 N 张 · 按下去 M 张」，按之前就知道这桌有几个人。
- **状态提示**（很重要）：
  - 显示「**真实模型 deepseek-chat**」→ 真的在用 AI
  - 显示「**离线模拟**」或「未允许真实模型」→ 没连上模型，这一场用的是内置模板

### 第二个分区：事件讨论（八个人，八卦性格）

台面上一共八个人。标题下面那两个按钮点一下就整套人换掉，当前分区用金色高亮。议题票的提示语、「开桌」按钮上的字、最后那份档案的名称都会跟着换——**不需要重开程序**。

事件讨论那八张牌上，名字是「卦名当姓」的绰号（乾明、坤兰、震山、巽竹、坎川、离霞、艮石、兑溪），名字下面是"在这桌上他是干什么的"，比如乾明是"定调子、拍板的人"。**鼠标停在牌上**能看到这个人来自哪个卦、阳面和阴面各是什么样。

商业痛点那九个人是职业视角；事件讨论这八个人是**以八卦为性格原型**的普通人。八卦在传统里不只讲吉凶，也讲性情——《说卦传》里一句"乾，健也；坤，顺也；震，动也；巽，入也；坎，陷也；离，丽也；艮，止也；兑，说也"，后人就是拿它引申性格的。我们只借它当"说话方式"。

| 席位 | 来自 | 阳面（好的一面） | 阴面（坏的一面） |
| --- | --- | --- | --- |
| 乾明 | 乾·天 | 刚健果断、扛事、先开口定调 | 刚愎、好面子、听不进人话 |
| 坤兰 | 坤·地 | 包容、有耐心、记得所有人的事 | 和稀泥、心里开始算账 |
| 震山 | 震·雷 | 反应快、敢说、有正义感 | 一惊一乍、爱起哄、传话添油加醋 |
| 巽竹 | 巽·风 | 消息灵通、会来事、说话让人舒服 | 两边传话、见风使舵、拱火 |
| 坎川 | 坎·水 | 深沉、看得透、一针见血 | 多疑、阴郁、专挑痛处 |
| 离霞 | 离·火 | 热情、明亮、爱美、明察 | 虚荣、爱面子、说翻脸就翻脸 |
| 艮石 | 艮·山 | 稳、有定力、有底线、不掺和瞎传 | 固执、闷、一句话噎死人 |
| 兑溪 | 兑·泽 | 会聊、幽默、谁都爱跟她说话 | 嘴碎、刻薄、爱看热闹、言多必失 |

（"来自"那一列只是来源标注；名字是"卦名 + 一个字"——乾明、坤兰、震山、巽竹、坎川、离霞、艮石、兑溪，八个名字互不相同，也能一眼看出对应哪个卦。）

**阴阳两面是这个分区的核心**：同一张嘴，好的一面和坏的一面会换着出现，而且**换面至少要隔三条发言**——不然"翻脸"就没有意义了。带阴阳面的发言会在发言人后面标出「（阳面）」或「（阴面）」。

这个分区唯一硬性的规矩是：**谁都不许把听来的说成确定的**。发言会分三种口气——"我知道"、"我听说"、"我猜"，角色要自己交代清楚。这也是它最像真实围观的地方：**大部分内容都只是传言**。

结束后的档案叫**「吃瓜纪要」**，六项一一对应原来的机会档案：

| 吃瓜纪要 | 原来是 |
| --- | --- |
| 这事儿算什么 | 机会方向 |
| 牵扯到谁 | 目标用户 |
| 有实锤的部分 | 支持理由 |
| 吵得最凶的地方 | 主要风险 |
| 还只是传言 | 待验证假设 |
| 接下来看什么 | 下一步行动 |

再提醒一次：**八卦性格是传统引申，不是心理学测评**，不能拿来判断真人；角色说的话也不是事实，只是"这种性格的人可能会这么说"。遇到真实事件里涉及的具体人物，请当作化名看。

## 五、圆桌界面怎么用

| 位置 | 内容 |
| --- | --- |
| 顶部 | 主题、当前阶段、生成状态、少量操作 |
| 中央 | 当前分区的席位（商业痛点九个／事件讨论八个）；**当前发言者高亮** |
| 中部 | 发言气泡（当前这一条发言）+ 底部一行小字提示 |
| 右侧 | 「完整记录」抽屉：全部发言，含发言人、阶段、意图、回应对象、来源 |
| 底部 | 下一步、暂停／继续、跳过、插话、结束并总结 |

底部按钮的作用：

- **下一步**：推进一条发言。键盘上按 **空格** 跟点「下一步」是一回事，看的时候手不用离开键盘。**系统不会自动翻页**——你没看完就不会自动换人、不会自动替换观点。
- **暂停／继续**：只暂停展示，不删除任何内容。
- **跳过**：直接看下一条。
- **插话**：你输入的内容会成为**最高优先级**，下一条会优先回应它；它**不会改写**已经发生的发言。
- **结束并总结**：停止讨论，用已保存的内容生成档案（商业痛点=机会档案，事件讨论=吃瓜纪要）。

## 六、发言里会看到什么

每条发言都带结构化信息，不再只是"一段话"：

- **类型**：这一条是什么性质，气泡上会直接写出人话解释（见下表）
- **阴阳面**（仅事件讨论）：发言人后面标「（阳面）」或「（阴面）」，表示这个人这一条用的是好的一面还是坏的一面
- **意图**：支持 / 反驳 / 追问 / 补充 / 整理
- **回应 XXX**：这条在回应谁（可回溯到具体某一条发言）
- **改变立场**：该角色修改了原有观点，可展开看变化前后的理由
- **主持人介入**：当出现重复增加、讨论冷场、某个分歧已充分交锋等情况时，主持人会出来收束，并**显示介入原因**
- **来源标签**：模型生成 / 离线模拟 / 用户内容

发言类型只有六种，气泡上显示为「假设（还没证据的推测）」这种形式，把鼠标停在气泡上能看到完整对照表：

| 类型 | 人话意思 |
| --- | --- |
| 机会 | 值得做的方向 |
| 风险 | 担心会出问题的地方 |
| 假设 | 还没证据的推测 |
| 待验证 | 需要去证实的 |
| 总结 | 阶段性归纳 |
| 事实 | 已经确认的情况 |

这个类型是**模型自己判断的**，不是程序判定的，所以偶尔会贴错；它只是帮你快速判断"这条要不要当真"，**不代表这条内容已被核实**。

### 现在是"人在说话"，不是"九份模板"

这件事单独说，因为它是这一版改动里最要紧的一条：

- **每条长短不一样**：有的只有一两句（三十来字，像抢话），有的能说上百来字，看当场有没有真东西可说。以前每条都是两三百字的整段，所以看着像九个人在交同一份作业。
- **各有各的说话习惯**：每个席位都写死了自己的口癖和句法（爱算钱的上来就报数，爱讲经历的只讲自己遇到的事，爱挑刺的一开口就反问"凭啥"）。所以同一件事，不同的人开口就不一样。
- **会点名叫人**：有回应对象时，第一句就点名字（"坎川你这话……"），不再对着空气发表看法。
- **不许套话开场**：像"我先说一句""实话实说""说白了"这类开场会被程序拦下来重写一次；也不许用"第一/第二/第三""首先/其次/最后"分条。
- **只做一件事**：一条发言要么接话、要么顶一句、要么补一个事实、要么问一句，不要求每条都把"表态＋理由＋条件＋反问"走一遍。

实测对比（同一件事、同样的八个席位）：改之前 20 条发言全部落在 154–257 字，"我先说…"占了八个开场里的六个；改之后 53–162 字，八个人开场各不相同，点名叫人的比例从 65% 升到 95%。

调度规则（可以理解为"谁该说话"）：优先回应用户插话 → 回答没人回答的提问 → 被反驳且尚未回应的角色回击 → 让久未发言的角色加入。为了不变成两个人对轰，**任何角色在最近六条发言里最多占两条**，两人交锋两轮后会换人。

这几条规则**对模型选的发言人也同样生效**：模型可以决定谁最该说话，但如果它连着挑同一个人，程序会按上面的上限换人。主持人收束也一样受限制——**主持人整理完之后，至少还要过四条角色发言才会再次整理**，不会一直由主持人说下去。

在结构规则之上，还有一层**由模型做的编排**：每次生成前，模型会读完整个事件流，决定"现在最关键的问题是什么、这一条必须回答什么、必须避免重复哪些已有点"，并顺手刷新共识／分歧／未解决问题。生成之后还会做一次**质检**：是否只是重复前文、是否回避了被指派的问题、是否编造了来源里没有的数据；不合格会带着**具体批评**重写一次。**主持人这一条也要过质检**。

如果某一条真的被质检打回重写过，**「完整记录」里那一行会写明**，例如：

```
【动态交锋】 用户研究员 · 风险 · challenge · 回应 普通路人 · 模型生成 · 质检重写：重复了 event-000012 的说法
```

没有这个标记就说明质检通过了——**它不会悄悄改内容却不留痕**。

所以**每点一次「下一步」会发 3～4 次请求**（编排 → 生成 → 质检，不合格再加一次重写），约 **7～8 秒**出下一条。这是为了"每条发言真的推进关键问题"付出的代价——如果你更在意速度，可以把 AI 关掉用离线模板，速度会快很多。

## 七、社会热点雷达

大厅点「社会热点」进入。**每次打开会自动刷新一次**，也有「刷新」按钮可手动重试。

条目分两类，**分开标注**，不要混看：

| 标签 | 含义 |
| --- | --- |
| **真实新闻源** | 来自公开新闻源，带**真实来源**和**真实发布时间** |
| **AI 回忆** | 由 AI 凭记忆生成。**AI 没有实时新闻能力**，条目上标注的时间与来源都是**模型自述**，实测多为一年以上前的事 |

两条重要提醒：

1. **两类都未核验**，不能当作已证实的事实。
2. 窄主题（例如"社区养老"）在当天头条里常常匹配不到，程序会**自动改为展示当前一般热点**，并在状态里说明。

其他行为：可按地区／类别筛选；刷新失败会**保留上次结果**并显示上次成功时间；不会安排定时后台刷新。

### 看到有意思的，直接开一场讨论

**点卡片上的「就这个话题讨论」，或者直接点卡片的空白处**，就会立刻以这条热点为题开一场讨论（自动切到**事件讨论**分区，坐八个席位——热点说白了就是"某事"，八卦那八个人更适合围观）：

- **主题**自动填成这条热点的标题；
- **条目本身作为讨论线索带进去**，而且**它的来源和时间是跟着走的**——AI 回忆的条目会写明"模型自述时间／来源、未核验、可能已过时"，真实新闻的条目会写明媒体和发布时间。这一点很重要：否则角色会把两年前的旧事当成今天的新闻来讨论；
- **参与角色用你在大厅勾选的那些**；如果大厅一个都没勾，会自动用**事件讨论的全部八个**（商业痛点则用全部九个），而不是开一场空圆桌；
- 这一场**不会再额外抓新闻**，因为素材就是这条热点本身。

## 八、机会档案与导出

点「结束并总结」后进入总结页，包含：

- 机会方向与目标用户
- 支持理由、主要风险、待验证假设、建议下一步
  - 事件讨论分区里，这六项显示为**吃瓜纪要**的六项：「这事儿算什么／牵扯到谁／有实锤的部分／吵得最凶的地方／还只是传言／接下来看什么」，顺序一一对应，**不是**另一套字段
- 当前共识、未解决分歧、未回答问题
- 各角色的立场轨迹
- 被质检打回重写过的发言（如果有）会在完整记录里带「质检重写」标记

点「导出」可保存 **Markdown** 或 **JSON**。导出内容包含完整事件流（含你的每一次插话）、机会档案、来源列表、实际使用的服务与模型、网络与生成状态、回退说明和 token 用量。

**导出文件绝不包含 API Key。**

## 十、分享给别人

- 分享**整个程序文件夹**（或那份打包好的 zip），保留 `_internal`。
- 接收者需要**自己填 API Key**——分享包里没有你的密钥、历史记录和缓存。
- 如果对方只有程序没有密钥，程序会自动走离线模板，界面会如实标注。

## 十一、已知限制（请务必知道）

1. **所有发言都是 AI 或模板生成的推断，不是已核验事实。** 来源列表不代表每条发言都有对应证据。
2. **AI 热点没有实时性**，可能是一年多前的事；程序会逐条标注模型自述的时间与来源。
3. **讨论质量取决于你配置的模型。** 换更好的模型，内容会明显不同。
4. **首批 14 条发言在后台生成**（开场 1 条 + 九个独立观点 + 三条交锋 + 总结 1 条）。九个"独立观点"是**并发**生成的，所以首批全部就绪约 **25 秒**；**第一条约 3 秒就出现**，其余在后台继续，界面会显示"正在后台准备后续发言…（N/14 条已就绪）"。
5. **每点一次「下一步」发 3～4 次请求、约 7～8 秒**，因为每条都要先编排、再质检（见第六节）。
6. 未获得授权的音频素材，所以**没有角色语音**，程序不会假装有。
7. 没有"自动播放"。这是设计决定，不是缺陷。

## 十二、常见问题

**双击没反应 / 打不开**
确认文件夹完整（必须有 `_internal` 子文件夹），不要只把 exe 单独复制出来。若被杀毒软件拦截，先放行再试。

**大厅显示"离线模拟"**
说明没连上模型：AI 设置未启用、密钥为空、模型名为空，或接口地址不对。程序会在大厅写出具体原因。

**弹出"讨论生成失败；请稍后重试"**
服务不可用或返回了异常内容。程序会如实说明并回退到离线模板，不会伪装成功。

**进去以后要等很久才有第一条**
正常情况约 **3 秒**出现第一条。若长时间空白，检查网络与服务地址。

**讨论中只有两个人在说话**
现在不会了。调度规则限制任何角色在最近六条发言里最多占两条。

**热点没有内容**
模型不可用或网络不通。程序会显示缓存结果和上次成功时间，而不是报假成功。

**怎么确认我用的是最新版**
看程序文件夹里 `使用说明.txt` 开头的"本次更新"日期；热点页条目上应有「真实新闻源 / AI 回忆」标签。
