# 九人圆桌对话模型实现设计

## 1. 目标与边界

本设计把 `2026-10-11-hybrid-nine-person-discussion-design.md` 已批准的讨论协议，在**真实模型路径**上真正落地。协议只写下了目标：混合点名、结构化意图、立场变化、状态整理、主持人介入。现状是这些在离线模拟路径上有部分实现，而在真实模型（DeepSeek/OpenAI 兼容）路径上基本空转。

本设计的**首要目标是讨论的有效性**：每一条发言都应当推进当前尚未解决的关键问题，而不是九个人轮流陈述立场。模型请求次数与 token 成本**不作为设计约束**，用户已明确表示可以多次请求。

同时保持的硬约束：不修改讨论协议本身；不修改存储格式（schema 仍为 v6）；不修改离线模拟路径；一次点击只显示一条发言（用户手动逐条展示，绝不自动播放）；总轮数不设上限。

已确认的决策：

| 决策 | 结论 |
| --- | --- |
| 优化目标 | **讨论有效性优先**，请求次数与成本不设限 |
| 离线模拟路径是否一起改造 | **不改**（用户一直联网使用，离线仅作故障兜底） |
| 状态整理由谁做 | **由模型做**，且并入编排调用，不单独占一次请求 |
| 手动逐条展示 | **保持不变，且必须有回归保护** |
| 总轮数 | **仍不设上限** |

## 3. 总体架构

在"生成一条发言"前后各加一层模型调用，并把本地结构分析降级为事实提供者：

| 单元 | 职责 | 联网 |
| --- | --- | --- |
| `brainstorm/turn_planner.py`（新增） | 本地结构事实：谁被反驳未回、哪个提问没人答、谁久未发言、重复计数。产出**事实**与**兜底计划**，不做语义相关性判断 | 否 |
| `brainstorm/orchestration.py`（新增） | 编排提示词构造与结果解析；质检提示词构造与结果解析 | 是 |
| `brainstorm/llm.py`（改造） | 底层请求、单条发言生成与解析、结构化标记 | 是 |
| `brainstorm/session_controller.py`（小改） | 驱动流水线、后台预取、把介入原因与新标记送到界面 | 否 |
| `brainstorm/engine.py`（不动） | 离线模板路径 | 否 |

分层意图：**本地算得准的交给本地（结构事实），本地算不准的交给模型（语义判断）。** 编排调用拿到本地算好的事实作为输入，因此不必重新推断"谁欠一个回应"，可以把注意力放在"现在真正的症结是什么"。

`turn_planner` 是纯函数，无副作用、不发请求、不碰界面，其全部规则可由普通单元测试覆盖。

**并发约束**：同一时刻只允许一条流水线在运行。重复点击复用正在进行的请求，不重复发起；用户插话会作废在飞与已预取的结果并重新编排。

## 4. 单条发言的流水线

一次点击最多触发 4 次模型调用，全部在后台线程执行：

**调用 A：编排（必发）**

输入：主题、全部用户插话、完整事件流（带 `event_id`／`intent`／被回应对象／立场变化）、本地结构事实与重复计数、上一次状态快照。

输出：

- 当前最关键、尚未解决的问题（一条，具体到可回答）
- 下一位发言人及其理由
- 这条发言**必须**回答什么（明确的指令，不是泛泛的方向）
- 必须避免重复的既有观点
- 是否应插入主持人整理，及介入原因
- **刷新后的状态**：共识、分歧、未回答问题、各角色最新立场

介入判断必须按协议 §2.1 的五个触发条件逐条检查，命中哪个就报哪个作为介入原因：新观点明显减少、重复增加、讨论冷场、重要共识出现、某个分歧已充分交锋。本地重复计数作为判断"重复增加"的证据输入。

即：编排调用**兼任状态刷新**，不额外占用请求。

**调用 B：生成（必发）**

按 A 的指令生成该角色的一条发言，输出结构化标记（`content`／`kind`／`intent`／`replies_to`／`stance_change`）。

角色被明确告知：编排建议的回应对象仅供参考，若认为不合适可以自行选择回应对象，并在 `intent` 中如实表达。

**调用 C：质检（必发）**

对一个刚生成的发言做三项判断：

1. 是否只是重复前文已有观点（附上重复的是哪一条）
2. 是否回避了本次被指派的回应目标或必须回答的问题
3. 是否编造了来源材料中不存在的数据、引用或事实

**调用 D：重写（仅当 C 判定不合格，最多一次）**

把 C 的具体批评回灌给模型重写同一角色的发言。重写后不再质检，直接采用。

若 C 判定合格，则本轮共 3 次调用。

**后台预取**：一条发言显示后立即在后台启动下一条的 A→B。用户点击"下一步"时若结果已就绪则直接显示，无需等待。预取结果**只在用户点击后显示**，不自动播放；用户插话会使已预取内容失效并重新编排，以保证插话必定影响后续发言。

## 5. 分期实施

### 5.1 第一期：让结构化标记真的可用（地基）

改 `llm.py` 的提示词与解析。质检与编排都建立在 `intent`、`replies_to`、立场变化之上，因此必须先做。

提示词改动：

1. JSON 形状增加 `intent`（`support|challenge|question|elaborate|synthesize|initial`）与 `stance_change`（可为 `null`，非空时必须含 `before`、`after`、`reason`、`triggered_by`）。
2. 前文渲染为 `[event-000012][阶段][intent] 姓名: 内容`，使模型能按 `event_id` 精确回指。
3. 明确要求 `replies_to` 填前文出现过的 `event_id` 或人名；不得重复前文已说过的观点。
4. `stance_change` 的 `reason` **必须同时写明"仍然保留的条件或疑虑"**——协议 §2.3 要求记录四项，而 `StanceChange` 只有三个文本字段，故第四项并入 `reason`，**不新增数据结构字段**，以免触碰 schema v6。

解析改动：

1. 按人名回指时取该角色**最新**一条，而非最早（修 G4）。
2. Anthropic 路径补上代码围栏剥离，与 OpenAI 路径一致（修 G5）。
3. `intent` 非法值回退 `initial`；`stance_change` 缺字段则整体置空，不因部分字段报错。

### 5.2 第二期：本地结构分析

`turn_planner` 产出结构事实与兜底计划，优先级与协议 §4.5 逐条对应：

| 优先级 | 事实 | 兜底发言人 | 理由文本（示例） |
| --- | --- | --- | --- |
| 1 | 存在未被回应的用户插话 | 尚未回应过该插话且发言数最少的角色 | 「你刚才插话，优先回应」 |
| 2 | 存在未被回答的 `question` | 该问题指向的角色，否则最久未发言的角色 | 「某人的提问还没有人回答」 |
| 3 | 存在被 `challenge` 且尚未回应的角色 | 被反驳者，回指那条反驳 | 「X 的质疑尚未回应」 |
| 4 | 某角色连续多轮未发言 | 发言数最少的角色 | 「让 Y 加入交锋」 |
| 5 | 无上述触发 | 发言数最少且最久未发言的角色 | 「补充已有观点」 |

兜底**不做语义相关性判断**：优先级 1、2 只用"是否已回应过""发言数多少""最久未发言"这类结构量；谁最适合回答由调用 A 判断。

这些事实同时作为调用 A 的输入。**兜底只在模型不可用或建议非法时生效**，正常情况下编排调用会给出更好的答案。

### 5.3 第三期：编排层与质检层（有效性的核心）

实现 §4 的调用 A→B→C→D，以及后台预取与并发约束。这是本设计中对"讨论是否有效"贡献最大的一期。

### 5.4 第四期：可靠性与长讨论

1. **格式错误重试**：解析失败时把错误回灌给模型重试一次。仅当重试仍失败才回退，并如实标注 `fallback_reason`（修 G8）。与协议 §6"自动重试一次"一致。
2. **重复检测**：本地按归一化文本（去空白、取前 80 字）完全比对，命中则置 `duplicate=True`，**只标记不删除**，并累加 `duplicate_count`。此为协议 §3.1"重复内容不删除，只增加重复标记和检测依据"的实现口径。
3. **长讨论上下文**：从"最近 12 条纯文本"改为三段式——常驻段（主题、主持人开题、全部用户插话，永不截断）、状态段（来自调用 A 的最新共识／分歧／未解决问题／各角色立场）、近段（最近 24 条带 `event_id` 与 `intent` 的完整发言）。24 为本设计选定的常量，覆盖约两轮半交锋。
4. **主持人介入发言**：由调用 A 的介入判断驱动，独立视觉样式并显示真实介入原因。
5. **结束总结多遍**：先抽取全部主张与证据线索，再按关键问题归组，最后成稿为机会档案与总结。用户真正保留的是这份档案，值得多一遍。

## 6. 界面呈现

- 气泡与字幕：显示发言人与被回应角色（"回应 XXX"）。
- 右侧记录：显示 `intent` 与"改变立场"标记（两者已在渲染，第一期后开始真正出现）。
- 主持人整理：独立样式 + 介入原因文本（`host_intervention_reason` 现已持久化但从未显示）。
- 状态区：共识／分歧／未回答问题来自调用 A；编排失败时显示上一次结果与时间。
- 生成状态区：后台预取就绪时显示"下一条已准备"；本条经质检重写时临时提示"本条经质检重写"。**两者都只作瞬时提示，不落盘、不新增存储字段。**
- 不新增工具栏、不改变全屏与窗口化行为。

## 7. 异常与降级

| 情况 | 处理 |
| --- | --- |
| 编排调用失败 | 回退到本地兜底计划，继续生成；如实标注为兜底编排 |
| 质检调用失败 | 视为通过并采用该条发言，但标注"未质检"，不阻塞讨论 |
| 模型返回非法 JSON | 回灌错误重试一次；仍失败则本条回退离线并如实标注 |
| 重写后仍不合格 | 采用重写结果，不无限重试 |
| 模型未返回 `intent` | 按 `initial` 记录；结构事实降级，仅使用不依赖语义的信号 |
| 模型建议的下一位非法 | 静默回退到本地兜底选择 |
| 用户插话时已有预取或在飞结果 | 作废并重新编排，保证插话必定影响后续发言 |
| 状态刷新失败 | 保留上次状态，标注失败与时间，不中断讨论 |
| 模型超时／网络错误 | 沿用既有重试一次后回退，不改变现有语义 |
| 模型整体不可用 | 沿用现有回退，界面保持"已回退到离线模拟"的诚实提示 |

任何情况下：不展示密钥、请求头或原始敏感异常；不把离线模拟结果标成模型生成；不把未核验内容写成已证实事实。

## 8. 测试与验收标准

**调度与结构事实**（纯单元测试，不联网）：覆盖 5 条优先级规则各自命中与互斥；兜底在模型建议非法时生效；"不会连续 3 次以上同一角色"。

**提示词与解析**：断言提示词**确实索要** `intent`、`stance_change`、`event_id`（G2 的本质就是没人测过提示词要了什么）；`replies_to` 指定 `event_id` 时精确落到该条；按人名回指取最新一条；代码围栏被剥离；畸形 JSON 触发一次重试且重试成功后不回退。

**编排与质检**（用假客户端）：编排结果中的发言人、必须回答的问题、状态刷新被正确解析并应用；五个介入触发条件分别能产生对应原因；质检判定不合格时触发且仅触发一次重写；质检或编排失败时按 §7 降级且不中断。

**重复检测**：重复内容被标记 `duplicate=True` 且条目不被删除，`duplicate_count` 正确累加。

**控制器**：**回归保护"一次点击只推进一条"**，不得破坏 `manual_advance` 行为；预取结果不得在用户点击前显示；并发约束下重复点击不产生重复请求。

明确验收口径：

1. 被反驳且未回应的角色成为下一位发言人，并回指那条反驳。
2. 用户插话后，下一位优先回应插话；已预取内容被丢弃。
3. 命中介入条件时生成主持人整理发言，介入原因非空并显示在界面。
4. 模型输出格式错误时先重试，重试成功则不回退离线。
5. 一次点击只多出一条发言，且预取不导致自动播放。
6. 长讨论中主题、开题与用户插话始终在上下文内。
7. 现有 127 项测试保持通过。

**必须由用户实测确认的部分**：第 1、2 期完成后，"谁回应谁"可由上述测试证明。但"讨论是否变得更有效、更深刻"**无法由单元测试证明**，需用户实际跑一场真实 DeepSeek 讨论后判断。此项不得由实施者代为宣称通过。

## 9. 明确不包含的内容

固定轮数上限；自动播放；角色语音；来源事实核验（不核验外部来源真伪）；离线模拟路径改造；新存储字段或 schema 版本升级；多候选并行生成择优；九个独立模型账户；记忆/状态之外的 UI 重做。
