# 事件讨论分区（八卦八人 · 阴阳两面）设计

日期：2026-10-26
状态：已与用户确认概念与席位命名，待实施

## 1. 背景

软件原本只服务一种问题：**商业痛点**（九种社会职业视角，产出「机会档案」）。
用户要加第二个分区：**对某件事的讨论**，也就是八卦——某件社会新闻、某个人、某个说法，几个人坐一起聊。

两个分区**人不一样**：
- 商业痛点区：保留现有九个职业头衔，行为不改。
- 事件讨论区：八个有性格的人，名字是口语绰号，卦只是他们的底色。

命名与性格的来源：
- 《说卦传》第七章（乾健、坤顺、震动、巽入、坎陷、离丽、艮止、兑说）与第十一章类象
  （震「决躁」、巽「进退、不果……其究为躁卦」、坎「加忧、心病……为盗」、
  兑「口舌、毁折」、坤「吝啬」）。
- 八卦属性总表（性格特征＋「需防……」）作为阳面／阴面的通行引申。
- 这些都写进席位 `prompt`，并注明「传统引申，不是心理学结论」。

## 3. 入口与切换

大厅顶部加两个标签：**商业痛点** ／ **事件讨论**。

切到事件讨论时：
- 席位列表从九个头衔换成上面八个人（`RoleChip` 显示名字 + 一句「这人是干什么的」）。
- 标题仍叫「九人圆桌」；副标题改成事件区的说法。
- 输入框占位符、示例按钮、底部说明、开始按钮文案随之切换。
- 档案页标题：商业＝「机会档案」，事件＝「吃瓜纪要」。

从社会热点雷达点卡片进来时，进入**事件讨论**分区（热点就是「某件事」）。

## 4. 语言规则（事件区专有）

- 一条发言 120–250 字，口语，可以带情绪，像聊天不像发言稿。
- 必须分清三种可信度，并且用词要看得出来：
  - 我确定的（有出处、公开事实）
  - 我听说的（传言，标「听说」）
  - 我猜的（纯推测，标「我猜」）
- **毒舌可以，造谣不行**：不许编造私生活细节，不许编造没有出处的「实锤」。
  阴面是刻薄，不是污蔑。
- 复用的是同一套 JSON 形状，`kind` 字段的取值映射换成八卦口径：
  机会＝看好、风险＝觉得要出事、假设＝听说的、待验证＝还没证实、事实＝已确认、总结＝归纳。

## 5. 阴阳翻面

- 八个卦开场都以**阳面**入席，先礼后兵。
- 被反驳、被戳到痛处 → 翻到阴面；被认同、被安抚可以翻回来。
- **冷却**：同一个卦翻面之后，至少再隔 3 条发言才允许再翻（防一秒一变）。
- 每条发言新增可选字段 `face`（`yang` / `yin`），缺省视为保持上一次。
- 记录里每条发言标「阳面／阴面」；主持人可以点破（「火姐这是翻脸了」）。
- 解析要宽松：`face` 非法或缺省一律不报错，按上一次的面向处理。

## 6. 吃瓜纪要（复用现有卡片数据结构）

| 字段 | 事件区显示为 |
| --- | --- |
| `title` | 这事儿到底算什么 |
| `audience` | 牵扯到谁 |
| `support` | 有实锤的部分 |
| `risks` | 吵得最凶的点 |
| `assumptions` | 还只是传言 |
| `next_steps` | 接下来看什么 |

不新增数据结构，`OpportunityCard` 直接复用，只在显示层按 `session.mode` 换标签。

## 7. 数据与兼容

- `DiscussionSession.mode`：`"business"`（默认）／`"event"`；旧存档缺这个字段时按 `business` 读。
- `Utterance.face`：默认空字符串。
- 存储 schema 仍是 6（只加可选字段，读写都向后兼容）。
- 模式的判定：按入席席位推断（八个卦的 id）——`mode_for_roles(roles)`，
  避免给 `discuss()` 等接口加参数导致全链路改动。

## 8. 非目标

- 不改商业痛点区的任何行为。
- 不做时间线视图。
- 不让模型自己选卦、不让用户手动指定「谁是阴面」——阴阳面由讨论过程自然触发。
- 不做「八卦词云」「关系图」这类可视化。

## 9. 验收

- 两套席位可在大厅切换，切换后席位列表、文案、档案标题都对。
- 事件区离线模板能跑完整一场，八个席位都说人话，不出现「机会／风险／目标用户」。
- 事件区真实模型一场：每条 120–250 字，出现至少一次翻面，记录里能看到「阴面」标注。
- 商业区回归：现有 248 个测试全过，档案仍是机会档案。
- 旧存档能打开，不报错。
