# 无限圆桌与沉浸式 UI 设计

## 目标

把“九人圆桌”从一次性固定轮次的播放原型升级为可持续讨论的桌面体验：用户可以让角色反复发言、回应和反驳，直到手动结束；结束后进入完整机会档案总结页。大厅和圆桌页同时完成响应式布局修整，使 1366×768、1536×864、1920×1080 和 Windows 高 DPI 下都能完整阅读。

## 交互设计

### 大厅

- 左侧是主题输入和素材区，右侧是角色选择区。
- 角色区使用可滚动网格，九个角色始终可见或可滚动到，不因窗口高度截断。
- 顶部显示离线/网络许可状态；主操作为“进入圆桌”。
- 角色卡显示姓名、职责和选中状态；保留全选、清空、四人快速。
- 提供明确的“退出”按钮；窗口模式通过“窗口化/全屏”切换。

### 圆桌

- 顶部只保留主题、阶段、生成状态和少量流程操作。
- 中央圆桌保持视觉主角；角色席位根据窗口尺寸缩放，当前发言者使用暗金呼吸式高亮。
- 底部显示当前气泡、字幕和用户插话入口。
- 记录抽屉用可见的滑出/收起动效呈现完整记录与来源。
- 操作包含“上一句/下一句”“暂停/继续”“结束并总结”“完整记录”“导出”“返回大厅”。

### 无限讨论与总结

- 初始生成后不再因为达到固定轮次而结束。
- 播放到当前记录末尾时，用户点击“下一句”会追加一批新的模拟对话；不设轮次上限。
- 追加批次允许同一角色多次发言，发言通过 `replies_to` 指向前一条观点，阶段标记为回应、反驳、补充或主持人追问。
- “结束并总结”停止追加，锁定讨论并显示总结页。
- 总结页完整展示机会标题、目标用户、支持理由、风险、待验证假设、下一步行动、观点分布和讨论统计；支持返回圆桌、保存、导出。
- 历史记录加载后默认视为已结束，仍可查看完整总结；不会自动联网或重新生成。

## 架构

- `MockDiscussionProvider` 保留初始离线讨论生成，并新增按会话上下文追加对话的方法。
- `SessionController` 增加 `extend_discussion()` 和 `finish_discussion()`，负责在当前 session 上追加 utterances、刷新播放和生成机会档案。
- `DiscussionPlayback` 不再把到达最后一句视为完成；只有显式 `finish()` 才进入 completed。
- `RoundtablePage` 使用可滚动角色面板和专用 `SummaryPage`，避免把完整档案压缩进一个气泡。
- 所有会话数据继续沿用现有 schema，新增统计字段时提供默认值，保持旧历史兼容。

## 诚实性与边界

- 离线追加内容明确标记为模拟观点；不伪装成真实模型回应。
- 真实模型生成失败时沿用现有安全回退。
- “暂停播放”只暂停展示；“结束并总结”才停止讨论生命周期。
- 不加入未经授权的音频、字体或外部图片。

## 验证标准

- 测试覆盖追加讨论、同一角色重复发言、回应关系、手动结束和旧历史加载。
- Qt offscreen 测试覆盖总结页、布局关键控件和窗口模式切换。
- 完整单元测试、编译检查和打包后的可见主窗口验证全部通过。
